# 喜娃微 PIA 选本与直播工作台

项目计划书 v0.7 · 现行范围整合稿 · 2026-09-30

**当前状态：本地工作台支持分类与剧本维护、分页/滚动展示、音视频手动走本、单篇 ZIP 交换和桌面独立展示器。当前日常资料为16篇，原14篇及手工修改保留。本轮按用户授权增加角色默认配色、编辑草稿与历史恢复、草稿排版预览、单篇及全库合并查重。** 操作见[使用说明](使用说明.md)，本轮规则见[编辑与导入](编辑与导入.md)，验证范围以[实施与验收记录](实施与验收记录.md)为准。

本稿在 v0.6 基础上整合后续已授权功能，文档版本 v0.7 不等于应用版本（目前为 0.1.0）。第11、13节保留早期审查及历次修订的历史含义。当前使用抖音直播伴侣窗口采集桌面独立展示器；用户已初步反馈最小化同步恢复，不能扩大为全部设备与声音场景的保证。本轮不包含联网 AI、平台推流、多人或公网部署。

## 1. 项目目标与已确认需求

制作一个在 Windows 本机运行的网页工作台，用于管理、查找和阅读 PIA 剧本，并生成可供后续直播采集的独立观众画面。

| 项目 | 当前范围 |
|---|---|
| 使用与部署 | 当前本人单机使用；本地运行，前后端不分离；保留未来局域网手机及公网扩展空间 |
| 功能重点 | 选本管理与直播展示同样重要，支持目录、简介和正文 |
| 内容维护 | 动态分类、正文文字/图片、角色默认配色、草稿/撤销/历史、真实排版预览、粘贴/TXT/DOCX 与 ZIP 交换、查重合并 |
| 展示流程 | 分类总览 → 分类内全部可见剧本 → 正文，返回逐层进行；本场列表保持自身范围 |
| 操作反馈 | 可选确认应用或实时同步；预览工具可放画面内或预览外 |
| 正文阅读 | 连续滚动、自动分页后人工翻页；已关联媒体的剧本新增音视频配本与手工时间点暂停 |
| 排版 | 默认竖屏，可切横屏；独立保存两方向设置，支持系统默认及最多 10 套自定义展示方案 |

| 直播边界 | 抖音直播伴侣窗口采集独立展示器，已有用户初步最小化同步反馈；不直接登录、开播或推流 |
| 本轮媒体范围 | 单篇关联本地音频或视频，手工时间点对应一段或多段文字/插图，自动或手动台词，横竖媒体分区；已完成本地验证和正式更新 |
| 未来方向 | AI 生成、转码/剪辑、语音识别、自动对齐/烧录、跨设备/多人控制仍未实现 |

“选本—预览—上屏—阅读—返回目录”已交付。下表合并既有能力与本轮媒体实现，新增媒体的最终交付状态以第 10 节及验收记录为准。

| 页面 | 现行能力与新增实现 |
|---|---|
| 选本页 | 分类总览与分类内完整剧本列表；检索剧名、作者、角色和关键词；按原配音备注筛选；查看已有简介与备注；加入本场并调整顺序 |
| 剧本阅读页 | 显示 PPT 收录正文、角色标签与配色、表演提示和必要插图；调整字号、行距；不显示 PPT 页码或页码导航，来源字段仍内部保留 |
| 播控页 | 直接交互预览、两层目录与正文导航、确认/实时反馈、画面内外工具、排版与展示方案、独立的即时播控 |
| 独立展示页 | 观众画面，显示目录或正文；支持滚动与人工分页；本轮加入音视频与台词分区。与有效实时预览同步位置和临时悬停反馈，不显示管理/预览操作栏 |

两层目录指“分类 → 剧本”的导航层级，分类数据仍是一层；每篇剧本归属一个当前分类。原六类是初始数据，不是固定槽位或数量上限。动漫影视本等普通空分类保留入口并显示空状态；系统“未分类”为空时隐藏。

### 3.1 动态分类与内容维护

分类可新增、查询、改名、修改说明/主题/显示状态、拖动或上下移动排序。名称去除首尾空格后不能为空或重名；稳定 ID 不随改名改变。选本、筛选和新预览采用同一分类顺序。

删除含剧本的分类时，必须选择有效目标分类或系统“未分类”，转移与删除在同一事务完成；取消或失败不删除剧本。“未分类”不能改名、隐藏或删除。隐藏分类及其剧本不进入新的可用选择，但管理页仍可编辑、恢复。

剧本可维护名称、作者、简介、原配音备注、标签、待核事项、显示状态及正文。当前分类与原 PPT 分类分别保存；现有段落的源文件、源页及 ID 保留，编辑写入历史记录，不覆盖原始 PPT。资料页面隐藏页码只改变显示，不删除来源映射。原文疑点仍按[来源内容核查](来源内容核查.md)保留待核。

### 3.2 分类背景素材

背景是分类属性，可选择、更换或清除。背景素材库支持本地上传、预览、改名和删除；分类编辑内上传后会选中素材，但保存分类才改变分类背景，取消编辑仍保留已上传素材。

- 上传只接受完整解码的静态 PNG、JPEG、WebP，最多 12 MB、2500 万像素、单边 12000 像素；伪造、截断或超限图片拒绝入库。
- 内置 PPT 背景保留；自定义图被分类、正文、当前上屏快照或修改历史引用时拒绝删除并说明原因。清除分类背景不自动删除文件；历史引用不能靠清除当前背景解除。
- 未引用的自定义图片及名称也纳入备份。上传或恢复写图片失败时清理本次半截文件，不删除原有完整同名资源。

### 3.3 正文导入与角色复用

内容管理支持粘贴文本、TXT 和 DOCX 的本地规则识别。先生成原文、标题、作者和角色候选预览，再由用户选择填入编辑草稿；只有正常“保存剧本”才写入资料库。取消、在途取消或识别错误不改变当前草稿。

默认追加保留全部原有块及其 ID/来源。明确替换时，只替换文字；现有插图及其 ID/来源按原顺序保留在新文字末尾。识别出的标题和作者只填补编辑器中的空字段。角色下拉候选来自正在编辑的同一剧本，可以复用已有名称或自由输入新角色；不汇总其他剧本角色，也不自动删除正文中的角色前缀。

当前解析边界：

- TXT 最多 2 MB，优先 UTF-8/BOM，失败后尝试 GB18030 并提示核对编码；文本最多 30 万字符、10000 行，单行最多 20 万字符。
- DOCX 最多 10 MB，解压总量最多 30 MB、512 个成员、单个 XML 最多 8 MB；按正文段落及表格顺序提取文字，保留制表和软换行，限制段数与总文字量，拒绝不安全路径、加密、非法压缩和 XML 实体。
- 标题、作者和“角色名：台词”由规则尝试识别；原始标题/作者行及非空行文字保留；纯空白行自动跳过且不计段落，完整原文另在对照区保留，角色不明确时保持未指定。不是在线 AI，也不保证自动判断正确。
- DOCX 不导入图片或执行 OCR；页眉、页脚、批注、脚注等附属内容不导入并提示。修订中的新增/删除文字均保留供核对；特殊字体符号或嵌入内容可能不能完整提取，会提示对照原文。
- 初始 PPT 内容由专用整理管线导入；通用 PPT/PDF 上传解析、自动补写简介和自动修订原文均不属于当前功能。

### 3.4 本地音视频配本

每篇剧本可选关联一份本地 MP4、WebM、MP3、WAV、M4A 或 OGG，单文件不超过 200 MB。文件流式读取、校验容器签名后按 SHA-256 保存；不信任客户端路径，不转码，不保证所有容器内编码都能被浏览器解码。无媒体的篇目继续使用纯正文滚动或分页。

- 阅读页和管理列表提供音视频入口；播控准备区所选剧本下方可打开“管理音视频与暂停点”。只有关联有效文件的正文可选第三种阅读方式“音视频配本 · 时间点暂停”。
- 用户播放、拖动并暂停，手工标记时间，再多选对应文字或插图。每个时间点至少关联一个稳定正文 ID；时间必须有效、非负、在已知时长内，按时间排序且不能重复同一时间值。同一时间需要多段时，在同一点多选；空时间点列表允许保存。
- 上传/替换/解除关联直接保存资料；时间点选择和编辑先留在本页，点“保存全部时间点”才入库。替换媒体清空旧时间点及旧时长；解除关联保留历史引用的文件。已有上屏快照不随资料修改改变。
- 到手工时间点媒体暂停，读完点“读完继续”。自动台词模式显示该时间点所选组；手动模式由“上句/下句”控制台词，时间点仍会暂停媒体。无时间点时可按正文定位，不会凭空生成时间轴。
- 竖屏上方媒体、下方台词；横屏左右分区且可互换。媒体模式切换横竖屏仍保留媒体；字幕模式、横屏媒体位置及其他排版随两方向配置和展示方案分别保存。
- 确认模式先预览再应用并暂停；实时模式同步明确操作及媒体位置。拖动进度会暂停。预览默认静音，实时绑定时锁定静音，避免双窗双声；观众浏览器可能要求点“播放”才允许有声播放。
- 播放位置、当前台词组及最近时间点纳入状态和备份；展示刷新/服务重启后保留最近保存位置并暂停。删除被时间点引用的正文前，须先调整关联。

详细操作、接口和样片状态见[音视频配本](音视频配本.md)。本轮不生成素材，不执行语音识别，不自动制作时间点，不转码/剪辑，不烧录字幕，不实施多设备或真实抖音采集。

## 4. 主要操作流程

1. 通过启动入口打开工作台，按分类检索、阅读，并整理本场列表。
2. 普通 `/control` 入口或刷新直接准备分类总览；不沿用旧 live 的平铺列表、已聚焦分类或正文。只有 `/control?script=<id>` 明确进入相应正文。
3. 选择分类范围或本场来源、画幅和反馈模式，在预览内逐层进入目录、正文并定位。准备模块的“剧本目录”按钮直达最外层分类总览且保留范围，预览返回工具仍逐层返回。分类未勾选表示全部可见分类；本场空队列保持空，不能回退成全库。
4. 使用“打开独立展示窗口”复用观众窗口。确认模式点击应用上屏，实时模式按第 4.1 节同步；当前在抖音直播伴侣中用窗口采集选择独立展示器；实际画面与声音按现场环境核对。
5. 根据正文模式使用滚动、人工翻页或已配媒体的时间点走本；即时播控位于预览底部，“暂停展示”常显，其余控件在“展示控制”中展开，只操作已上屏内容。

管理保存与上屏是不同操作。分类改名、排序、隐藏、迁移、删除或正文修改，不直接改写已经上屏的快照；快照保留当次名称、主题、内容和排版。跨页资料变更后，必须取得有效新预览，不能把旧预览令牌对应的未见内容直接上屏。

### 4.1 预览、即时播控和恢复的默认规则

本节整合当前两种反馈模式；v0.4 的“应用后才替换画面”基线继续适用于确认模式。

| 操作 | 当前行为 |
|---|---|
| 普通播控入口或刷新 | 以最新保存的横竖排版生成分类总览草稿，不写 live、不暂停观众画面；即使记住实时模式，也不自动发布初始草稿 |
| 确认模式操作预览 | 切目录/正文、选段、试滚、翻页、调整排版均先留在预览；点击应用后内容、画幅、段落及适用页/媒体位置一起上屏并暂停 |
| 主动切换实时模式 | 取得当前就绪预览的实际位置与播放状态后同步；之后用户发起的导航、定位、翻页、排版及开始/暂停自动同步 |
| 即时播控 | 预览底部常显暂停，展开“展示控制”可操作当前上屏的滚动、分页或媒体；不附带或覆盖未应用草稿 |
| 切回确认模式 | 丢弃尚未发送的自动任务并解除连续绑定；已经发送的请求可能已经生效，不回滚已上屏内容 |
| 陈旧预览或同步错误 | 拒绝不一致输入并停止自动同步；重新核对预览后手动应用/重试，不无限自动重发 |
| 换本与同本应用 | 未明确指定预览位置时，新篇目从起点；同篇保留仍有效的段落/条目，失效回起点并提示；指定预览位置时以该位置为准 |
| 展示窗口刷新或服务重启 | 恢复已应用快照与最近保存的位置，并保持暂停；不把播控首页总览草稿当成恢复内容 |
| 刷新选本、管理或播控页 | 只重新读取资料/状态，不更改现有直播内容、播放或位置 |

正文分页只由人翻页，不启动自动滚动；目录仍可滚动。分页同时保存源段落锚点和适用页位置，使长段跨页时的“应用”能够带上当前预览页。同内容可保留页位置；版式、字体或方向改变后需要重新分页并按语义位置恢复，页号不能作为跨字体、跨排版的永久地址。

上屏快照固定内容、布局、媒体关联与时间点，当前速度、暂停状态及段落/页/媒体位置是独立运行状态。状态版本与定位版本区分新命令，普通轮询不重复定位。暂停/手动定位及时保存，滚动时节流保存检查点，不逐帧写数据库；意外关闭不承诺像素级恢复。

### 4.2 直接交互、工具与同浏览器同步

预览支持点击分类、剧本、正文定位及逐层返回，工具提供前后段、顶部、试滚、字号和适用的上一页/下一页。操作栏可选画面内移入显示或预览外；外置与应用按钮处于同一操作区，15px 字号、至少 44px 点击高度，窄屏换行。位置与确认/实时模式是独立设置，保存在当前浏览器。观众画面不出现这些操作控件。

有效实时绑定在同一浏览器、同一站点会话的两个窗口间连续发送即时画面位置、播放和临时悬停反馈；确认模式、草稿变更或同步错误解除绑定。分类、剧本卡片和正文的悬停效果可同步；断流后临时焦点清除。控播页进入后台时观众可继续滚动，返回时优先查询观众实际位置，无回复时短超时后按时间估算。

此处的连续位置同步不是跨浏览器或跨设备能力。HTTP 状态轮询用于持久状态和兜底；同浏览器通信不代替服务端校验。当前按一个观众窗口使用，推荐通过命名窗口入口复用，避免多个展示同时回传检查点。

## 5. 横屏、竖屏与排版方案

视口宽度大于 1040px 时，左侧准备与设置模块的合计高度跟随右侧预览面板，中间设置区可独立滚动，标题、画幅方向及保存入口保留；小于或等于 1040px 时按“准备 → 预览 → 设置”堆叠，设置自然展开。本轮把原独立即时播控块移到预览底部，暂停常显，其余收进“展示控制”；保存和确认/实时规则不变。

| 项目 | 当前实现 |
|---|---|
| 逻辑画布 | 竖屏 1080×1920、横屏 1920×1080，按比例适配；这是项目设计值，不是已验证的抖音强制规格 |
| 独立配置 | 横竖分别保存字号、行距、边距、整页背景浓度、分类列数、分类背景浓度、正文阅读方式、媒体台词模式、横屏媒体位置及默认速度 |
| 分类排列 | 自动或固定 1/2/3/4 列；自动最多竖屏两列、横屏三列，少量分类相应减少；动态分类生成，不写死六项 |
| 单列摘要 | 左侧分类条、右侧摘要；悬停或键盘聚焦显示最多三篇已有剧本的标题、简介、作者和原配音信息，点击进入完整目录；空类显示空态 |
| 背景浓度 | 分类卡片图片单独 0–100%，默认 80%；0%隐藏图片，100%最清晰。整页背景浓度另行控制 |
| 正文 | `scroll` 连续滚动；`pages` 按实际画幅、字号、行距、留白自动排页，长段可跨页，人工上一页/下一页；`media` 为有文件的剧本提供时间点暂停和台词分区 |
| 保存当前画幅 | 单独保存当前方向设置，重新进入时优先使用最新保存值，旧 live 快照不覆盖新设置 |
| 展示方案 | 一套独立系统默认值和最多 10 套自定义方案，每套包含两方向完整排版；名称不能为空或重名 |

保存、改名、覆盖或删除方案，只维护方案本身，不应用 live，也不替代当前画幅设置；更新/覆盖和删除有确认。选择方案不立即载入，点击“载入方案”才更新预览两方向排版；确认模式待应用，实时模式同步当前预览。载入系统默认不删除自定义方案，系统默认本身不能改写或删除。

背景可按画面裁切，文字和插图保持可读；实际抖音遮挡与安全区需现场核对，不能写死未经验证的尺寸。分页按浏览器实际字体测量，重排后需核对页数和当前位置；分页异常会提示调整字号或留白重试，不代表已生成固定出版页。

## 6. 视觉与阅读原则

保留原 PPT 的六类初始主题，新增分类使用通用主题或自选背景；改名、排序不改变主题关联。正文不沿用原 PPT 过窄文字栏，使用清楚的角色标签、颜色和可调字号/行距；理解角色不只依赖颜色。

分类图片移除过厚遮罩，文字局部浅底保留可读性。单列分类悬停轻微放大至 1.04 倍并加深背景；摘要限制在画布可见范围，摘要打开时内置浮栏暂时避让，键盘仍可访问工具。预览与独立展示的目录/正文切换约 270 毫秒，选本页阅读往返也有短转场，并尊重系统减少动态效果设置。

## 7. 已采用的技术与数据组织

当前采用 **Python + Flask + Jinja + SQLite** 单体应用，Windows 通过 Waitress 运行。页面、JSON API、静态资源与 SQLite 由同一项目和本地服务提供；浏览器 HTML/CSS/JavaScript 承担交互、滚动、实际测量分页及同源窗口通信，没有另建独立前端服务。背景图片由 Pillow 校验；文本/DOCX 解析使用本地规则与标准库。锁定依赖及独立运行环境见[运行环境](运行环境.md)。

| 数据 | 实际保存内容 |
|---|---|
| 分类与剧本 | 稳定 ID、当前分类、原 PPT 分类、资料字段、顺序、主题与显示状态 |
| 正文与来源 | 稳定段落 ID、顺序、角色、文字/颜色片段、插图、原稿来源与原文；编辑历史保留旧内容 |
| 内容核对 | 现有备注与待核事项、源记录和修改历史；没有另设自动裁决原文疑点的流程 |
| 排版 | 两方向配置，含 `category_columns`、`category_background_opacity`、`body_mode=scroll|pages|media`、`media_caption_mode` 和 `media_side`；独立 `default_layouts` 与最多 10 套 `layout_presets` |
| 背景库 | 本地资源路径、素材名称、内置标记和图片信息；未引用自定义素材也可备份 |
| 剧本媒体 | `media` 保存路径、类型、名称、大小、SHA-256、可选时长及手工 `cues`；每点保存时间、名称和稳定 `block_ids` |
| 当前场次 | 本场队列、已应用快照、模式/目录层级/聚焦分类、段落或条目锚点、适用页位置、`media_state` 的秒数/台词序号/最近时间点、播放/速度及版本 |

`list` 快照通过 `directory_level=categories|scripts` 和 `focus_category_id` 区分两层导航；正文仍为 `script`。旧未传新字段的 API 请求保留平铺兼容，普通网页入口按第 4 节统一进入分类总览，两者不混用。

预览只生成候选快照；内容令牌覆盖内容、主题、选择、画幅和完整排版，应用前重新校验。SQLite 事务原子保存内容/定位/状态；失效输入不部分上屏。正文分页使用稳定块锚点和可选 `page_index`，页数由浏览器决定，服务端不猜测版面页数。媒体 `preview_media_state` 必须有有效预览令牌；媒体命令检查快照及可选状态版本，检查点必须匹配 revision。旧资料通过读取时默认值兼容，不覆盖原正文。

轻量 HTTP 轮询同步持久状态，同源窗口通信传递即时画面位置；不逐帧写数据库。分类删除先迁移关联剧本，图片删除检查资料、快照与历史引用。新字段为旧设置、快照和备份补默认，保留现有内容、稳定 ID 和导航语义。

默认只监听本机并校验本机 Host、写入来源与 CSRF。ZIP 恢复验证成员路径、大小、哈希、数据库结构与内容，不直接执行上传数据库；先保存恢复前备份，再原子替换工作资料。这些机制服务于当前本机应用，不等于已实现联网账户和权限系统。

## 2026-09-30 编辑与导入改进

用户已批准工程实施，范围包括以下四项：

1. 每篇剧本设置角色默认色，新句选角色时采用默认色；未设置则从正文首个有效配色推导。默认色的调整不改原句，统一已存在台词需显式操作；手动单句颜色仍可保留。
2. 编辑草稿在当前浏览器/桌面会话本地保存，按服务地址、资料目录与剧本隔离；重新打开可选择恢复。草稿不代替正式保存或资料备份。提供会话内撤销/重做以及已保存版本的历史恢复，恢复前保存当前正式版本。
3. 编辑器使用当前草稿和已保存画幅设置进行真实分页/滚动预览，支持横竖切换、放大及点击台词定位编辑；不发布快照，不改变直播状态。音视频播放仍使用原配本页与播控页。
4. 单篇 ZIP 和完整备份“仅合并剧本”先只读查重。内容相同跳过，同名不同默认跳过、可显式覆盖，无同名时可新增。覆盖需指定目标并校验检查后的变化，保留目标剧本 ID、队列及已上屏快照；保存覆盖前历史。仅合并不导入分类主题、全局设置或原备份历史；完整恢复仍是替换资料的独立操作。

新增内容通过既有数据库与资源验证，不重新导入原 PPT，不重新打包整个项目。当前功能及维护细节见[编辑与导入](编辑与导入.md)。
