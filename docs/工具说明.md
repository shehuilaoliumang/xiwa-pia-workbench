# 工具说明

项目自带两个维护工具，都在 `tools/` 下，都用项目自带的运行环境执行：

```powershell
runtime\python.exe -X utf8 tools\<脚本名>.py
```

> 两个工具都**不会**改动 `instance/`（你的真实资料）、`runtime/`、`vendor/`、`evidence/`、
> `.backup/`、`.local-archive/` 与 `desktop/runtime/`。

---

## 一、`tools/customize.py` — 自动化定制向导

把通用模板改成一个新领域的工作台：改配置中心、批量替换全局文案与标题、重命名种子分组、
更新文档标题与 README，并输出变更清单与「需人工处理」清单。

### 常用命令

```powershell
# 交互式向导（推荐第一次用）
runtime\python.exe -X utf8 tools\customize.py

# 只看当前生效配置
runtime\python.exe -X utf8 tools\customize.py --show

# 先预览，不写任何文件
runtime\python.exe -X utf8 tools\customize.py --dry-run --non-interactive --yes `
  --name 播客工作台 --slug podcast-workbench --port 8801 `
  --item 单集 --group 专辑 --groups "访谈,故事,杂谈"

# 正式执行（加 --yes 跳过确认）
runtime\python.exe -X utf8 tools\customize.py --non-interactive --yes `
  --name 播客工作台 --slug podcast-workbench --port 8801 --item 单集 --group 专辑
```

### 参数

| 参数 | 说明 |
| --- | --- |
| `--show` | 打印当前配置后退出 |
| `--dry-run` | 只预览：算好规则与命中文件，但不写配置、不改文件、不重命名种子 |
| `--non-interactive` | 从命令行参数取答案，不提问（适合脚本化） |
| `--name` / `--short-name` | 新应用名 / 短名 |
| `--slug` | 英文标识（小写+连字符），同时用作 `app_id`、包名、备份格式前缀 |
| `--port` | 默认端口（1024–65525） |
| `--item` / `--group` | 「条目」「分组」在本领域的叫法 |
| `--groups` | 默认分组名，逗号分隔 |
| `--tagline` / `--brand-mark` | 副标题 / 页眉角标字符 |
| `--drop-display-module` | 把展示/播控模块**标记为关闭**（只改配置，不删代码） |
| `--skip-seed` | 不重命名种子数据里的分组 |
| `--skip-smoke` | 跳过定制后的冒烟测试 |
| `--yes` | 跳过最终确认 |

### 它会做什么

1. 写入 `config/template.json`。
2. 按「旧配置值 → 新配置值」推导出的有序映射，在**白名单文本文件**上批量替换；
   每个被改文件先备份到 `.backup/customize-<时间戳>/`。
3. 按顺序重命名 `data/seed.json` 里的分组显示名（保留 id 与条目归属）。
4. 打印可裁剪模块清单与「需人工处理」清单。
5. 跑冒烟测试（`/api/health`、`/`、`/control`、`/manage`）并扫描旧值残留。
6. 把变更清单写到 `.backup/customize-<时间戳>/customize-report.md`。

### 安全边界

- **不做全库盲目正则替换**：只应用由配置差值推导出的映射，且只作用于白名单文本文件
  （`.py/.js/.cjs/.html/.css/.md/.txt/.cmd/.json/...`），二进制（图片、Office、PPT、ZIP、EXE）一律不动。
- **改前必备份**，并在 `customize-report.md` 里逐文件列出改了什么、命中哪条规则。
- **不删除功能**：`--drop-display-module` 只写配置标记。
- 无法自动处理的（截图、图标、文档内嵌图片里的文字）进「需人工处理」清单，见
  [定制指南](定制指南.md)。

## 二、`tools/build_package.py` — 一键免安装交付包

一条命令产出可交付的 ZIP：检查运行时与依赖 → 可选构建 EXE → 收资源 → 打包 → 产物自检 → 输出清单。

### 常用命令

```powershell
build.cmd                       # 双击或命令行运行
build.cmd --skip-exe            # 只打包，不构建 EXE（最快）
build.cmd --with-editor         # 额外构建「内容编辑器」EXE
build.cmd --rebuild             # 覆盖已存在的产物
build.cmd --help                # 查看全部参数
```

### 前置条件

1. 运行环境已准备：`python tools\prepare_runtime.py`
2. （桌面版需要）Electron 运行时已准备：`runtime\python.exe -X utf8 tools\prepare_desktop_runtime.py`
3. 构建 EXE 需要 PyInstaller；默认不会自动联网安装，除非显式 `--install-pyinstaller`

### 产物

| 路径 | 内容 |
| --- | --- |
| `dist/<slug>-portable-<version>-<日期>.zip` | 免安装交付包（内置启动/停止脚本、README、docs） |
| `dist/<同名>.manifest.json` | 交付清单：ZIP 与包内每个文件的大小、SHA-256、被排除项、跳过的步骤与原因 |

**不进入交付包**：`.git/`、`.backup/`、`.local-archive/`、`instance/`、`evidence/`、`.qa/`、
`__pycache__/`、`tests/`、`*.pyc`。`instance/` 是你的真实资料，**绝不**打包。

### 边界

不发布、不推送、不 `git commit`；是否重建已存在的 EXE 由 `--rebuild` 决定。详细说明见
`tools/BUILD-USAGE.md`。

## 三、其他维护脚本（一般不需要直接跑）

| 脚本 | 用途 |
| --- | --- |
| `tools/prepare_runtime.py` | 从纯源码副本重建 `runtime/`（便携 Python + 锁定依赖，需联网、带 SHA-256 校验） |
| `tools/prepare_desktop_runtime.py` | 下载并校验 Electron 桌面运行时到 `desktop/runtime/` |
| `tools/templating.py` | 替换引擎（被 `customize.py` 调用）：白名单、有序映射、改前备份、残留扫描 |
| `tools/stop.py` | 只关闭本项目的工作台服务，不误杀其他进程 |
| `tools/import_sources.py` | 维护者专用：从归档的原始 PPT 重建种子数据（模板内不含原始 PPT，需先放回 `.local-archive/evidence-originals/`） |
| `tools/package_release.py` | 旧的免安装包流程；新流程请用 `tools/build_package.py` |
