## 3. 本轮已确定的设计边界

媒体文件与正文分离，时间点引用稳定正文 ID；不会删除原文、图片或来源信息。一个时间点至少选择一块，可同时选文字和图片。修改时间点先留在编辑草稿，保存才入库；文件上传/替换/解除关联另行即时保存。替换清空当前时间点，历史及上屏快照保留原媒体。若要删除被时间点引用的正文，先调整时间点关联。

媒体到点暂停，自动模式显示该点所选台词，手动模式保留人工选择的台词；两者都可读完继续。拖进度暂停，回到起点可重新走本。字幕是网页内独立正文区，不是识别音轨或写入视频的字幕。

预览与已上屏内容仍分离：确认应用带上预览位置并暂停，实时同步由明确操作驱动；管理保存与页面刷新不自动替换已上屏快照。媒体刷新、重启和恢复备份保留最近保存位置并暂停，不承诺逐帧时间精度。

无媒体的篇目继续正常选本、阅读、滚动和分页。“帮别人翻页”表示操作者在本机控制同一观众画面，不等于远程控制他人电脑。

## 4. 后续仍须单独确定的方向

- **生成与导入**：是否接入 AI 生成、多个素材或外部服务，另行讨论；当前只关联用户提供的本地文件。
- **自动字幕**：ASR、自动对齐、字幕文件与烧录不包含在手工时间点中，不能将已有文字识别导入当作音频识别。
- **媒体制作**：转码、剪辑、混音、循环策略、多轨道及精细构图均未承诺。浏览器不能解码时提示更换合适文件，不在后台自动转码。
- **多设备**：手机访问、多个观看者或控制者、权限和交接需重新明确；现有同桌面应用／同浏览器通信不等于跨设备同步。
- **直播接入**：用户使用抖音直播伴侣窗口采集；独立展示器已复用 Python 服务并随项目集成，采集目标改为“喜娃微PIA · 独立展示”。2026-09-18用户初步反馈最小化同步“似乎已经解决”。该反馈不扩展为所有设备、采集方式、媒体编码和声音均已通过；后续环境变化再针对性核验。
- **使用门槛**：用户明确暂不考虑OBS。优先把展示组件集成到现有项目，保持一键启动及原播控操作；先验证直播伴侣现有窗口采集，不要求用户额外配置直播中转软件。若必须改变输入方式或安装额外组件，应先说明真实使用步骤，不能将其当成已接受方案。
- **同步档位**：已实现30／60／90／120档网页同步目标，默认60并显示实际收发频率，本机偏好随桌面验证版验收；媒体时间校准独立保持约10Hz。网页同步目标不能标为直播伴侣实际采集FPS。

## 5. 本轮验证与未来验证的分界

本轮已验证文件上传、手工多选文字/图片、到点暂停和继续、拖动进度、确认/实时隔离、横竖分区、预览静音锁定、旧资料与媒体备份恢复；还覆盖 0 秒时间点、回退重触发及后台/即时暂停的位置保护。样片初次关联时未预填时间点，之后以用户当前保存的标记为准。测试入口见[维护与文件索引](维护与文件索引.md)，正式页面核验见实施记录；有声自动播放仍受浏览器交互权限约束。

未来若正式启用多设备或外部 AI，再增加访问权限、控制权争用、网络断开和外部服务数据边界测试。这些不是本轮本地媒体的验收承诺。
