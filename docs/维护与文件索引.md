## 文件与目录职责

| 位置 | 内容及维护方式 |
|---|---|
| `app.py` | 同源页面/API、导入入口、本机请求保护和响应头 |
| `storage.py` | SQLite、分类/剧本、已应用快照、即时命令、分页/媒体位置、媒体上传/时间点、方案和备份恢复 |
| `script_package.py` | 单篇剧本 ZIP 的校验、资源清单及导入导出；与全库备份格式分开 |

| `run.py`、启动/停止 `.cmd`、`tools/stop.py` | 独立启动、端口处理、同资料目录单实例和停止 |
| `templates/` | Jinja 页面结构，与同一 Python 服务一起提供 |
| `static/app.js`、`static/app.css` | 选本、管理、播控操作页及样式 |
| `static/display.js`、`static/display*.css`、`static/preview.css` | 观众画布、交互预览、悬停及窗口同步；后台布局/滚动、可见性恢复与展示窗口状态回报 |
| `static/pagination.js` | 浏览器实测分页、跨页文本和行内颜色保留 |
| `static/import-editor.js`、`static/import-editor.css` | 导入窗口、AI 整理提示词、识别预览和填入草稿 |
| `static/script-package.js`、`static/script-package.css` | 单篇 ZIP 的检查、分类选择和新增导入 |
| `templates/media_editor.html`、`static/media-editor.js`、`static/media-editor.css` | 音视频上传、播放器定位、手工时间点及多块正文选择 |
| `static/media-player.js`、`static/media-player.css`、`static/media-pagination.js` | 媒体/台词分区、到点暂停、自动/手动台词、进度和声音状态 |

| `data/source_extraction.json` | 原始结构、文字 runs、颜色和源页等提取结果 |
| `tools/import_sources.py` | 重建来源派生产物及内容核对报告，不读写用户数据库 |
| `instance/workbench.sqlite3` | 日常可编辑资料、设置及展示状态；用户后续修改以此为准 |

| `evidence/` | 原 PPT、需求截图和清单，保持原件；有新版本时另存，不覆盖旧证据 |
| `requirements.txt`、`tools/runtime-lock.json` | 应用依赖与独立运行环境锁定记录 |
| `runtime/`、`vendor/` | 项目便携 Python、依赖和离线安装材料 |
| `tests/` | Python 测试与浏览器操作测试；浏览器测试可能新增、覆盖或恢复资料 |
| `.qa/` | 隔离测试库、结果、截图和诊断证据，不作为日常数据源 |

`.gitignore` 排除 `instance/`、`runtime/`、`vendor/`、`.qa/` 等目录。只复制 Git 源码不等于完整交付或完整备份；迁移方法见使用说明。

## 维护流程

1. 阅读项目上下文和本次用户要求，核查相关代码及实际数据。初始14篇、历史直播状态和旧验收截图都不能代替当前状态。
2. 修改功能时同步对应使用说明；范围改变时更新计划和上下文。历史验收保留原结论及当时规则，若已被修正就明确标注。
3. 按改动运行必要测试，写入测试使用新建独立资料目录；确认/实时边界、正文保真和来源字段是重点。
4. 更新日常服务前保存资料ZIP；重启后核对健康状态和原资料，正式页面验证尽量只读。不要为通过测试回滚用户操作。
5. 在实施记录追加实际结果和限制；没有运行的测试不能写成当次通过。仅文档整理检查链接和一致性即可，不需要重启应用。

提取脚本会重写 `data/seed.json`、`data/source_extraction.json`、`docs/内容导入核对.md` 并补齐原图。若需调整生成报告的固定文字，应同时处理其生成来源；日常文本导入说明放在使用说明中，避免下次生成被覆盖。
