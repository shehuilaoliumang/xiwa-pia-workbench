## 9. 启动问题修复（2026-10-04 追加）

**现象**：双击 `启动工作台.cmd` 后只出现黑色控制台窗口，不出现任何工作台界面。

**排查过程**

1. 复现用户路径（`runtime\python.exe -X utf8 run.py`）：服务正常启动、`/api/health` 返回
   `ok=true`，但 **electron 进程数为 0**，`instance/desktop.log` 为空 —— 界面从未打开。
2. 定位到两个叠加原因：
   - **`run.py` 缺少启动校验与回退**：`open_interface()` 在 `Popen` 之后直接 `return`，
     只要 `electron.exe` 存在就永远走桌面分支；桌面进程随后死掉也不会退回浏览器，
     于是既不出现桌面窗口、也不打开浏览器。
   - **本机 Chromium 沙箱无法初始化**：`electron.exe` 用默认参数启动时**无声立即退出**
     （退出码 0、无任何输出，Windows 事件日志留下 `electron.exe` APPCRASH `0x80000003`）。
     已确认这**不是**本会话沙箱造成的：在不受限模式下同样失败。
3. 逐项验证：

   | 尝试 | 结果 |
   | --- | --- |
   | 默认参数（`electron.exe main.cjs ...`） | 立即退出，无输出 |
   | `--no-sandbox` | **成功**：4 个进程，窗口标题 `内容管理工作台 · 桌面版`，无 FATAL/ERROR |
   | `--no-sandbox --disable-gpu` | 同样成功，但强制软件渲染，会影响展示窗口流畅度 → 不采用 |

**修复内容**

- `run.py`：新增 `spawn_desktop()` 与 `survives()`；桌面宿主必须存活超过
  `desktop.startup_grace_seconds` 才算启动成功；失败则用 `desktop.sandbox_retry_args`
  重试一次；仍然失败则打印原因并**自动打开浏览器版**。控制台会明确说明用了兼容参数。
- `config/template.json` / `template_config.py`：新增 `desktop.startup_grace_seconds`（6）
  与 `desktop.sandbox_retry_args`（`["--no-sandbox"]`），模板使用者可调整或关闭。
- `tests/test_desktop_launcher.py`：原用例把 `Popen` 模拟成一个「已退出」的进程，
  与新契约不符，已改为模拟存活进程；并新增 2 个用例覆盖
  「首次失败→兼容参数重试成功」与「两次都失败→回退浏览器」。
