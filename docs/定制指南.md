# 定制指南：把通用模板换成你自己的领域

这份模板默认是一个**通用内容管理工作台**：本地运行、只监听 `127.0.0.1`、用「分组 / 条目」组织内容，
并可选带一个展示（播控）模块和一个独立的「内容编辑器」子项目。

换成新领域时，**优先走自动化**：

```powershell
runtime\python.exe -X utf8 tools\customize.py
```

向导会改配置中心、批量替换全局文案与标题、重命名种子分组、更新文档标题与 README，
并输出变更清单与「需人工处理」清单。想先看效果而不落盘，加 `--dry-run`：

```powershell
runtime\python.exe -X utf8 tools\customize.py --dry-run --non-interactive --yes `
  --name 播客工作台 --slug podcast-workbench --port 8801 --item 单集 --group 专辑 `
  --groups "访谈,故事,杂谈"
```

下面列出**向导覆盖不到、必须人工处理**的部分，以及每一处的验证检查项。

---

## 1. 配置中心（自动）

| 文件 | 作用 |
| --- | --- |
| `config/template.json` | 唯一配置来源：应用名/短名、端口、页面与窗口标题、术语表、包格式名、备份前缀、默认分组、模块开关 |
| `template_config.py` | Python 读取器，带内置默认值兜底；缺文件也能启动 |

**约定**：全项目只通过 `template_config` 的常量与 Jinja 全局（`app_name`、`terms.*`、`tagline`、
`brand_mark`）引用这些值，不要再硬编码。

**验证检查项**

- [ ] `runtime\python.exe -X utf8 tools\customize.py --show` 输出的应用名/端口/术语与预期一致。
- [ ] 临时删掉 `config/template.json` 后服务仍能启动（走内置默认值），然后恢复该文件。

## 2. 种子数据（半自动）

`data/seed.json` 是首次运行时建库用的示例内容；`data/source_extraction.json` 是抽取证据。

向导只会**按顺序重命名分组显示名**（保留 `id`、字段结构与条目归属）。条目正文、角色名、
图片与来源文件名需要你按新领域自行替换。

**验证检查项**

- [ ] `runtime\python.exe -c "import json;json.load(open(r'data/seed.json',encoding='utf-8'))"` 无报错。
- [ ] 删掉 `instance/` 后首次启动，分组数与条目数与 `data/seed.json` 一致。
- [ ] 系统「未分组」组名与 `config/template.json → terms.uncategorized` 一致。

## 3. 页面与静态资源文案（半自动）

`templates/` 与 `static/` 里的**正文文案**由向导按术语表替换；但下面这些换领域时通常要重写：

| 位置 | 说明 |
| --- | --- |
| `templates/*.html` 的 `{% block title %}` | 已改为 `{{ terms.* }} · {{ app_name }}`，一般无需再动 |
| `templates/catalog.html`、`manage.html`、`control.html` 的正文说明文字 | 按领域重写措辞 |
| `static/app.js` 等用户可见提示语 | 按领域重写措辞 |
| `static/*.css` 的主题色 | 改配色变量即可，不影响功能 |

**验证检查项**

- [ ] `/`、`/control`、`/manage`、`/script/<id>` 四个页面返回 200，标题正确。
- [ ] 浏览器控制台无 JS 报错；`nav` 三个入口文案与术语表一致。
- [ ] 页面里不出现上一个领域的专有名词。

## 4. 图标与截图（必须人工）

向导**不会**改图片。以下位置需要你替换：

| 位置 | 处理方式 |
| --- | --- |
| `docs/guide-assets/*.png` | 使用说明截图：图内文字仍是旧应用名，需重新截图或修图 |
| `static/media/ppt-*.png`、`*.jpeg` | 演示素材：确认是否含旧领域文字 |
| `static/*.png`、`favicon` | 应用图标：替换为你的图标 |
| `docs/*.docx` | 文档正文已改写，但内嵌截图里的文字需人工核对 |

**验证检查项**

- [ ] 用图片查看器逐个打开上述图片，确认无旧应用名/旧领域词。
- [ ] 浏览器标签页与窗口标题不显示旧名称。

## 5. 模块裁剪（可选，默认不删代码）

模板按模块组织，`config/template.json → modules` 控制开关。想瘦身时按需删文件，
**不要**在功能还在用的情况下删公共代码。

| 模块 | 开关 | 相关文件（参考） |
| --- | --- | --- |
| 展示/播控同步 | `modules.display_sync` | `templates/control.html`、`templates/display.html`、`static/display.js`、`static/display-directory.css`、`static/media-pagination.js` |
| 音视频配本 | `modules.media` | `static/media-player.js`、`static/media-player.css`、`templates/media_editor.html` |
| 单篇内容包交换 | `modules.content_packages` | `script_package.py`、`static/script-package.js`、`static/library-merge.js` |
| 独立「内容编辑器」子项目 | `modules.editor_subproject` | `内容编辑器/` 整个目录 |

**验证检查项**

- [ ] 关掉某模块后，`/api/health` 与主页仍正常，未删代码路径无 500。
- [ ] 真的删了文件时，`runtime\python.exe -X utf8 -m unittest discover -s tests -p "test_*.py"` 仍通过。

## 6. 文档（半自动）

`README.md`、`PROJECT_CONTEXT.md`、`docs/*.md` 的标题与正文由向导批量替换旧名称，
但**叙述口径**需要你按新领域通读一遍。

**验证检查项**

- [ ] README 首段读起来是新领域的介绍，不是"内容管理"的模板说明。
- [ ] 文档里提到的路径与文件名真实存在（尤其 `docs/` 与 `内容编辑器/`）。
- [ ] 旧应用名残留扫描为空：

```powershell
runtime\python.exe -X utf8 tools\templating.py --patterns "旧应用名" "旧英文标识"
```

## 7. 打包与交付

```powershell
build.cmd                     # 或： runtime\python.exe -X utf8 tools\build_package.py
```

用法见 `tools/BUILD-USAGE.md`。打包会排除 `instance/`、`evidence/`、`.backup/`、
`.local-archive/`、`.git/`、`tests/`、`__pycache__/`。

**验证检查项**

- [ ] `dist/` 下生成 ZIP 与同名 `.manifest.json`，清单里 SHA-256 与实际文件一致。
- [ ] 在干净目录解压 ZIP，双击 `启动工作台.cmd` 能打开并显示新名称。

## 8. 已知需要人工决策的项

- **原始证据资料**（`evidence/` 与三份原始 PPT）属于来源证据，模板交付里已移出到
  `.local-archive/evidence-originals/`；换领域时应整体替换为你自己的来源资料。
- **Git 历史**：被移出的大文件仍存在于既有 git 历史对象库中；要彻底清除需
  `git filter-repo` / BFG 级别操作，属于破坏性操作，请自行确认后再做。
- **`data/source_extraction.json` 的原始页面正文**保留了来源材料里的原始标签用词，
  这是"抽取证据"的原文；如果你要求模板内 100% 无原领域词，需要明确决定后统一替换。

## 9. 一键自检清单

```powershell
runtime\python.exe -X utf8 tools\customize.py --show                 # 配置是否符合预期
runtime\python.exe -X utf8 -m unittest discover -s tests -p "test_*.py"   # 单测
build.cmd --skip-exe                                                  # 打包冒烟（含产物自检）
```

三项都通过，就算完成一次领域切换。
